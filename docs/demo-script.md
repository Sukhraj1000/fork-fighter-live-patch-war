# Fork Fighter two-minute demo script

## 0:00–0:15 — value

“Fork Fighter is an endless runner that can change while you play. Three Game Masters watch the same compact performance signal and invent attacks in parallel, but a deterministic referee keeps control of the game.”

Click `START SEEDED DEMO` or `START LIVE RUN`.

## 0:15–0:35 — stable game first

“The player only needs one control: jump. Time alive and Fork Shards build the score. The game starts immediately; it never waits for a model.”

Jump once and point to the rising score and run clock.

## 0:35–0:55 — parallel creativity

“Architect wants coherent systems, Gremlin wants disruption, and Auditor wants measured pressure. They draft independently from bounded telemetry, not from browser access or source-code access.”

Point to the three Game Master rows and the drafting/proposal activity.

## 0:55–1:15 — referee and announcement

“Every candidate is typed. The referee checks schema, capability, cleanup, route playability, difficulty and novelty. You can see one unfair candidate rejected and one safe candidate selected. Only one patch may be live.”

Point to the rejection, selection and incoming countdown.

## 1:15–1:35 — visible mutation

“The selected demand is now changing the actual run: gravity, runner movement, world style or a telegraphed hazard. The card names who authored it, what it does and how long it lasts.”

Point to the patch title, demand list, validator stamp and the changed runner/hazard.

## 1:35–1:50 — deterministic cleanup

“The agent does not execute arbitrary code. A fixed interpreter applies only supported effects. When the timer ends, tagged objects are removed and physics returns to baseline.”

Point to the expired event and restored game.

## 1:50–2:00 — Daytona proof and close

“In live mode, the footer and runtime endpoint prove these are three private Daytona-hosted Codex workers. Match end deletes those workers. Provider failure cannot stop scoring, input, death or restart.”

Close with: “The idea is parallel AI creativity with a deterministic game referee: wild enough to surprise the player, bounded enough to stay playable.”

## 30-second contingency ending

“The live provider is slow, so I am switching to the seeded path rather than hiding the failure. It runs the same typed boundary without network dependence. Here are three parallel drafts, a visible rejection, one selected patch and the effect entering the real game. Daytona supplies isolated creative workers; the referee and stable shell remain authoritative.”
